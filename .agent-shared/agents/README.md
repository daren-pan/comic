# 子 agent 协作协议（comic 项目）

> **目的**：把开发工作按「设计 → 开发 → 测试 → 运维」四个过程拆给四个专职子 agent（每个只做本职类工作）；由**负责人（项目负责人）**作为团队唯一对外接口与协调中枢 —— 用户的**需求 / 询问先到负责人**，由负责人分析后派发；子 agent 完成后向负责人报告；跨子 agent 的协助与问题由负责人代为表达；全部完成后由负责人向用户提交**统一汇总报告**。子 agent 之间**禁止直接对话**，保证交流信息全程公开。
> **载体说明**：平台侧可扩展面是「专家 / 技能 / 连接器」，而「多角色同时协作」由主对话派发子 agent 实现 —— 本目录的角色卡就是各子 agent 的**常驻定义**（主 agent 派发时按卡生成指令，子 agent 第一步先读自己的卡）。

## 角色总表

| 角色 | 一句话职责 | 定义文件 |
|---|---|---|
| 负责人 lead | 团队唯一对外接口与协调中枢：接需求 → 分析 → 派发 → 收报告 → 代为中转 → **统一汇总报告**（由主对话 agent 担任，不另行派发） | `lead.md` |
| 设计 design | 出方案：需求 → 模块落位、接口/数据形状、验收标准；只出方案不写实现 | `design.md` |
| 开发 dev | 落实现：按已批准的设计写/改代码与配套文档，自测后提测 | `dev.md` |
| 测试 test | 独立验证：对照验收标准实测复核，出缺陷报告与回归结论 | `test.md` |
| 运维 ops | 保上线：部署影响、上线检查、回滚要点、运行态巡检 | `ops.md` |

## 沟通拓扑（硬规则）

```
用户 ↔ 负责人（主对话 agent） ↔ 子 agent（design / dev / test / ops）
```

1. **子 agent 之间禁止直接对话** —— 不得互相发消息；违反视为流程违规，须在汇报中标注。
2. 子 agent 的跨角色请求 / 交付，**一律先提交负责人**，由负责人转达给目标子 agent（间接交流）。
3. 负责人的每一次派发 / 中转 / 收报都**留痕公开**；转发时保留原意，不得截留或改写。
4. 子 agent 只与负责人通信；负责人只与用户和子 agent 通信。

## 一轮工作流

1. **接单与分析**（用户 → 负责人）：用户的需求 / 询问先到负责人；负责人分析并拆解成子任务、按依赖排序（通常 设计 → 开发 → 测试 → 运维）。
2. **派发**（负责人 → 子 agent）：以任务卡（目标 / 范围 / 输入 / 验收标准 / 相关文件）派发给对应子 agent。
3. **执行与报告**（子 agent → 负责人）：只做本职；完成后向负责人报告；需要其他子 agent 协助或有问题的，**不直接联系对方**，提交负责人。
4. **代为中转**（负责人）：把 A 的请求 / 交付转达给 B（保留原意；公开留痕）。
5. **统一报告**（负责人 → 用户）：相关子 agent 全部完成后，提交**一份**汇总报告 —— ① 需求 / 目标；② 各子 agent 结论（含证据）；③ 中转记录；④ 待拍板事项；⑤ 下一步。

## 交流矩阵（全部经负责人中转，保留原意）

| 逻辑流向（实际路径：A → 负责人 → B） | 内容 |
|---|---|
| 设计 → 开发 | 设计说明、验收标准、边界清单 |
| 开发 → 测试 | 提测说明：改了什么、怎么验、已知风险 |
| 测试 → 开发 | 缺陷报告（复现 / 期望 vs 实际 / 证据）；回归结论 |
| 测试 → 设计 | 验收标准歧义或缺失，回给设计修订 |
| 运维 → 开发 | 环境约束、配置要求、上线注意（迁移 / 重启 / 回滚） |
| 开发 → 设计 | 实现中发现设计问题，回报修订，不自行改设计 |
| 子 agent → 负责人 | 汇报 / 请求中转 / 阻塞 |
| 负责人 → 用户 | 统一汇总报告 / 待拍板事项 |

## 质量门与红线（全部角色适用）

- 只做任务卡范围内的改动；**不自行扩展**；有疑问先回报。
- **不自行 commit / push**；提交须用户明确指令；信息按 Conventional Commits、按主题原子拆分、攒批提交。
- **不落临时文件**：探针 / 一次性验证用内联命令（`python -c` / `node -e`），不留 `_probe.py` 之类残骸。
- 改动后按约定重启对应服务（见根 `AGENTS.md`）。
- 提交前检查：无意外删除、无硬编码密钥。
- 性能红线：批量方法，禁 N+1 / 代价随数据量线性增长的写法。
- 踩坑即写对应模块 `NOTES.md`。
- **未经验证不得声称「通过」**；结论必须给证据（路径 / 行号 / 命令输出）。
- **沟通红线**：子 agent 之间禁止直接对话；一切跨角色交流经负责人中转并留痕；负责人不得截留或改写原话。

## 扩展

新增角色（如「需求 / 产品」）：复制任一张角色卡 → 改定位 / 职责 / 边界 / 交接 / 沟通规则 → 登记到本表。角色卡越「窄」越好 —— 一个角色只干一类事。
