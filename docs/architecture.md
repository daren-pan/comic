# 漫画聚合网站整体架构设计方案

> 数据来源：对其他漫画网站的抓取聚合
> 版本：v1.0 ｜ 日期：2026-09-02

---

## 0. 方案概述

本方案面向「内容聚合型漫画平台」：数据来自多个外部漫画源站，经采集管道入库后，为用户提供浏览、搜索、在线阅读、收藏与历史记录等核心能力。整体采用**五层架构**（应用层 → 服务层 → 存储层 → 采集层 → 数据源层），核心原则：

- **采集与业务解耦**：源站变动只影响采集层，不影响用户侧稳定性；
- **存储职责分离**：关系数据（MySQL）、热数据（Redis）、搜索索引（ES）、图片资源（OSS+CDN）各司其职；
- **全量低频 + 增量高频**：以最小抓取成本维持内容新鲜度；
- **学习用途定位**：本项目仅供本地技术学习与演示，不对外发布、不商用；数据源优先开放授权（CC/公共领域）站点，为学习多源接入可纳入其他站点受限样本，相关风险由项目方自行评估承担（详见 §6.2）。

## 1. 核心功能模块

| 模块 | 功能点 | 关键设计 |
|---|---|---|
| 漫画浏览 | 首页推荐位、热门榜单、最新更新、分类入口 | 热度 = 1000 起底 + 浏览次数×1 + 收藏数×2，**实时计算不落库**（权重集中定义于 `storage/mysql/_util.py` 的 `HEAT_*`）；"最新更新"直接消费抓取增量 |
| 搜索 | 按名称/作者/标签搜索，支持拼音、模糊匹配、搜索历史 | ES 索引 + 中文分词 + pinyin 插件；搜索热词 Redis 缓存 |
| 分类 | 题材（热血/恋爱/悬疑…）、地区（国漫/日漫/韩漫/美漫）、状态（连载/完结） | 多条件组合筛选，分类计数缓存 |
| 详情页 | 封面、简介、作者、状态、评分、章节列表、相关推荐 | 章节按 chapter_no 排序；连载漫画提供"追更"；详情 5 分钟缓存 |
| 在线阅读 | 图片懒加载、翻页/长条模式、亮度调节、进度记忆、失败重试 | 虚拟滚动渲染 ±2 页，预加载下一页，退出自动上报进度 |
| 收藏与历史 | 收藏夹增删/分组、阅读历史续读/清除、多端同步 | user_favorite 唯一约束防重复；read_history 按 updated_at 倒序取"最近在读" |

## 2. 数据抓取与更新策略

### 2.1 抓取来源

- **多源聚合（3~5 个源站）**：1 个主源 + 2 个备源，备源用于交叉验证与失效切换；
- 优先接入**提供公开 API / RSS** 的站点，其次才是页面解析；
- 源站信息（base_url、robots 允许、优先级、解析器类型、抓取间隔）全部配置化，存于 `source` 表，可动态增删启用。

### 2.2 抓取频率

| 任务类型 | 频率 | 内容 |
|---|---|---|
| 全量扫描 | 每日 1 次（凌晨低峰） | 兜底同步全部作品元数据，校正遗漏 |
| 增量轮询 | 每 15~30 分钟 | 仅轮询各源"最近更新"列表，抓取新章节 |
| 图片转存 | 懒触发 + 热点预取 | 用户访问章节时按需转存；热门漫画可预缓存；转存并发 2 路（`images.transfer.CONCURRENCY`），对境外图床显著提速 |
| 失效巡检 | 每小时 | 转存未转存页 + **全表**键集分页校验已转存对象，缺失则恢复/标记失效 |

### 2.3 去重策略

- **站内唯一**：`source_id + 源站内容ID` 建唯一记录，重复抓取幂等覆盖；
- **跨站合并**：标题归一化（去空格/符号、同义映射）生成 `fingerprint`，`fingerprint + author` 命中则合并为同一作品，避免同一漫画重复入库存多份；
- **章节去重**：`comic_id + chapter_no` 联合唯一；`content_hash` 用于内容变更检测（源站修图后可感知并重抓）。

### 2.4 反爬处理（合规框架内）

- **遵守 robots.txt 与服务条款**，优先公开 API/RSS；
- 请求限速：随机延迟 + UA 池轮换 + 自建 IP 池轮换；
- 失败重试采用**指数退避**，避免风暴式重试；
- **不绕过登录、验证码等技术壁垒**（详见合规红线，§6）。

## 3. 数据库与存储设计

### 3.1 关系型数据（MySQL 主从，读写分离）

核心表 8 张，分为「内容模型」与「用户行为」两组：

**内容模型**

| 表 | 关键字段 | 说明 |
|---|---|---|
| comic 作品 | PK id, title, author, cover_url, status, category, **fingerprint(唯一)**, source_id FK, latest_chapter_no, sync_time | 跨站合并后的作品主表 |
| chapter 章节 | PK id, comic_id FK, chapter_no, title, source_chapter_id, page_count, **content_hash**, sync_time | comic+no 联合唯一 |
| page 分页 | PK id, chapter_id FK, page_no, source_url, **oss_url**, cached_status | 图片不落库，只存 URL |
| source 源站 | PK id, name, base_url, robots_allowed, priority, parser_type, crawl_interval, status | 采集配置中心 |
| sync_log 日志 | PK id, source_id FK, task_type, total/ok/fail_count, started_at, finished_at, error_msg | 同步审计与版权存证 |

**用户行为**

| 表 | 关键字段 | 说明 |
|---|---|---|
| user 用户 | PK id, nickname, avatar_url, password_hash(哈希), role, created_at | 密码仅存哈希 |
| user_favorite 收藏 | PK id, user_id FK, comic_id FK, group_name, created_at | user+comic 唯一约束 |
| read_history 历史 | PK id, user_id FK, comic_id FK, chapter_id FK, page_no, updated_at | 存页码，精确续读 |

### 3.2 缓存（Redis 集群）

- 热点数据：详情页 5min、章节列表 10min、榜单/分类计数按需；
- 阅读进度：Redis + 落库双写，防丢失；
- 分布式锁：保证抓取任务全局只执行一份。

### 3.3 图片资源（OSS + CDN）

- 二进制全部放对象存储，按 `comic_id/chapter_no/page_no` 分目录；
- 统一处理链：转存 → WEBP 压缩 → 缩略图 → CDN 预热；
- `cached_status` 标记转存状态，未转存的页由图片服务懒触发转存任务。

### 3.4 搜索索引（Elasticsearch）

- 冗余索引 title/author/tags/description，中文分词 + 拼音搜索；
- 增量同步（抓取入库后异步写索引），失效章节同步删除。

## 4. 后端服务架构

### 4.1 服务划分

```
API 网关（JWT 鉴权 · 限流熔断 · 路由转发）
 ├─ 漫画服务：作品 / 章节 / 阅读
 ├─ 搜索服务：ES 检索
 ├─ 用户服务：收藏 / 历史 / 登录
 ├─ 采集服务：抓取 / 解析 / 入库
 └─ 图片服务：转存 / 裁剪 / URL 签名
基础设施：MySQL · Redis · ES · OSS+CDN · MQ · 调度器 · 配置中心 · 监控日志
```

### 4.2 接口设计（RESTful，统一响应 `{code, message, data}`）

| 模块 | 接口 |
|---|---|
| 浏览 | `GET /api/comics?category=&sort=&page=` |
| 搜索 | `GET /api/comics?keyword=&page=` |
| 详情 | `GET /api/comics/{id}`、`GET /api/comics/{id}/chapters` |
| 阅读 | `GET /api/chapters/{id}/pages` |
| 收藏 | `POST /api/favorites/{comicId}`、`DELETE /api/favorites/{comicId}` |
| 历史 | `GET /api/history`、`PUT /api/history/{comicId}` |
| 采集管理 | `GET /api/admin/sources`、`POST /api/admin/sources/{name}/toggle`、`POST /api/admin/sync`、`POST /api/admin/transfer`、`GET /api/admin/tasks`、`GET /api/admin/tasks/{id}` |

### 4.3 缓存策略

- **三级缓存**：CDN（图片/静态）→ Redis（详情/列表/榜单，更新时主动删除 + 过期兜底）→ 本地缓存（超热点）；
- 采集入库成功 → 主动删除相关缓存 Key → 下次请求回源重建。

### 4.4 任务调度

- 调度器管理三类任务：**全量扫描**（每日）、**增量轮询**（15~30 分钟）、**失效巡检**（每小时）；
- Redis 分布式锁保证全局单实例执行；
- 抓取任务投递 MQ 异步消费，长任务不阻塞调度线程；任务幂等，可安全重放；
- **手动触发（采集管理控制台 `/#/admin`）**：采集/懒转存/失效巡检为长任务，由后端 `threading.Thread` 后台执行 + 前端轮询任务状态（`GET /api/admin/tasks/{id}`），不阻塞 HTTP；支持按源开关（`source_state.json` 持久化）、手动指定起始日期 `since`（采集**优先于同步水位**）、采集数量 `limit`（受控样本），以及懒转存"仅转存某源"（`source` 参数）+ 起止日期 `since`/`until`（**双端含当天**；语义为「把窗口内所有未转存页全部转掉」，**无数量上限**；完成后自动顺带执行封面自愈 `scheduling.heal.heal_covers`）；**失效巡检**（`POST /api/admin/inspect`）在转存基础上再做「已转存对象**全表**校验 + 丢失恢复」（键集分页遍历，不截断）。任务结果汇入前端顶栏**消息中心**（未读角标 + 全局提示，离开管理页仍跟踪）。

## 5. 前端技术栈与页面布局

### 5.1 技术栈

- **核心**：Vue 3 + Vite + TypeScript + Pinia + Vue Router + axios（单通道接后端，拦截器统一 token/401/响应解包）；
- **UI**：自研组件库 / Naive UI；图片懒加载指令 + 骨架屏；
- **阅读器专项**：虚拟滚动 + 前后页预加载、翻页/长条模式、亮度调节；
- **多端**：响应式 H5，可复用 Taro 小程序；CI/CD 自动构建部署。

### 5.2 页面布局

- **首页**：顶部导航（Logo / 搜索 / 首页 / 分类 / 最近更新 / 排行 / 我的 / 管理）→ Banner 推荐位 → 热门榜 + 最新更新（并列）→ 作品网格（猜你喜欢）；
- **最近更新页**：按更新时间的卡片网格（分页），卡片带相对时间角标；
- **排行页**：按分类分区（作品数 ≥3），块内按**热度**取前 10（热度 = 1000 起底 + 浏览×1 + 收藏×2，后端实时算），区块滚入视口才懒加载；
- **分类页**：左侧多维筛选（题材/地区/状态）+ 右侧作品网格，分页加载；顶栏「分类」直达；
- **详情页**：封面 + 简介 + 收藏/追更按钮 + 章节列表 + 相关推荐；
- **阅读页（移动端）**：顶部返回/书名/目录 → 图片流（虚拟滚动）→ 底部上一章/亮度/进度/下一章；
- **我的页**：收藏分组、最近在读（续读跳转）、阅读设置。

## 6. 可扩展性与合规性

### 6.1 可扩展性

- **源站可插拔**：采集层抽象 `CrawlerAdapter` 接口，新增源站 = 新适配器 + 配置注册，不改业务代码；
- **水平扩展**：服务全部无状态，可横向扩容；MySQL 读写分离、ES 分片；
- **存储抽象**：对象存储统一接口，OSS/COS/MinIO 可替换；
- **任务幂等**：source+ID 去重，重复执行不产生脏数据；
- **流量兜底**：三级缓存 + 限流熔断，热门更新时系统稳定。

### 6.2 合规与责任声明（学习用途，风险自负）

1. **适用范围（学习用途）**：本项目定位**本地技术学习与架构演示，不公开发布、不对外提供访问、不商用**。数据源优先选择已授权、开放版权（CC）或公共领域内容；为学习「多源站接入/适配器开发/聚合去重」等技术，允许在本地环境纳入其他站点（含未授权转载站）的**受限样本**——样本规模受控（近期更新列表级）、仅本机访问、不随任何形式对外传播、演示完成后可清理。使用者自行评估并承担相关法律与合规风险；内容一旦用于公开部署/对外服务，必须移除全部未授权内容并回归授权源站策略；
2. **抓取边界（建议尽量遵守，违反自担风险）**：优先遵守目标站 robots.txt 与条款、优先公开 API/RSS；学习场景下如需突破反爬限制，仅限技术研究且样本受控，不进行规模化抓取与流量攻击；
3. **内容审核**：接入文本 + 图像审核，违规内容自动拦截；漫画内容分级，未成年人保护与防沉迷；
4. **用户数据**：遵循《个人信息保护法》，密码哈希存储、行为数据脱敏、提供注销渠道；
5. **内容溯源**：`sync_log` + `source_id` 保留内容来源链，便于识别与定向清理（如按 source 一键删除未授权样本）。
