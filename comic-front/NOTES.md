## 条目模板（新增知识时按此写）

**坑 / 决策 / 事实 —— 一律用这个字段块**（有就写、没有可省，字段名保持一致）：

```markdown
#### 标题（一句话说清是什么）

- **日期**：YYYY-MM-DD（多个用 ` / ` 分隔）
- **背景 / 现象**：发生了什么（决策类写"当时的背景"）
- **根因**：为什么会这样（决策类写"为什么这么定"）
- **结论**：怎么解决 / 最终决定是什么
- **实测**（可选）：关键数字 / 验证方式
- **位置**（可选）：涉及的文件 / 页面
```

**三种形态的选用**：

| 内容类型 | 形态 |
|---|---|
| 单条坑 / 决策 / 事实 | **字段块**（上面的模板） |
| 同质清单（多条结构相同的规则 / 调整 / 映射） | **表格** —— 列头即字段（如「默认行为 → 归一化」），不必逐条展开 |
| 操作规程（排查流程等） | **步骤结构**，不套字段块 |

日期尽量保留原始记录（这个项目的历史都带日期）。

### 1.2 桌面端适配整体删除（2026-09-23）

- **背景 / 现象**：comic-front 原先是一套**响应式**前端（基础样式是桌面态，靠 `@media (max-width: 860px)`
  反向覆盖成移动态）。两端互相牵制、样式难以维护。
- **根因**：用户决定把两端**彻底分开** —— 「移动端启动这个端口、网页端启动 comic-web 端口，端口区分开、
  改成两个 docker 镜像」。于是本端只保留移动形态。
- **结论**：**改造手法不是「删样式」，而是「把移动态提为基础态」**：

  | 原来 | 现在 |
  |---|---|

## 二、uni 适配的坑

### 2.1 `uni-compat.css`：内置组件样式归一化

- **背景 / 现象**：comic-web 的样式表是按**原生** `input` / `button` / `form` 写的；搬到 uni 后被编译成
  **内置组件**（`uni-input` / `uni-button` / `uni-form`），组件**自带默认样式 + 一层多余结构**，
  于是「CSS 一字未改却错位」。
- **根因**：uni 内置组件不复刻原生元素的默认表现（display / 垂直居中 / padding / 字体全变了）。
- **结论**：`src/uni-compat.css` 只做一件事 —— **把 uni 组件归一化回原生元素的盒子模型**（不改业务、不改模板结构）。
  11 条规则（清单类，保留表格）：

  | # | uni 的默认行为 | 归一化 |
  |---|---|---|
  | ① | `uni-form` 在子元素外**再包一层 `<span>`** | `uni-form > span { display: contents }`（否则 flex 从未生效） |
  | ② | `uni-button` 默认 `display: block` | `display: inline-flex`（否则按钮占满整行） |
  | ③ | `uni-button` 用 `line-height: 2.5555` **近似**垂直居中 | `align-items/justify-content: center`（业务一改 line-height 文字就贴顶） |
  | ④ | `uni-button` 默认 `margin-left/right: auto` | `margin: 0`（否则 flex 行里被吸到两端） |
  | ⑤ | `uni-button` 默认 `padding: 0 14px`、`font-size: 18px` | 还原原生 `1px 6px` / `13.3333px` |
  | ⑥ | `uni-button` 默认 `overflow: hidden` | `overflow: visible`（否则未读红点被裁掉） |
  | ⑦ | `uni-button` 用 `::after` 画 1px 边框 | `html uni-button::after { border: none }` |
  | ⑧ | `uni-input` 写死 `height: 1.4em` + `box-sizing: border-box`，内层又 `height: 100%` | `height: auto; min-height: 0` + 内层 `height: auto`（否则只给 padding 时**输入框高 0px、点不进去**） |
  | ⑨ | `uni-input` 默认 `line-height: 1.4em` | `line-height: normal` |
  | ⑩ | uni 组件**继承 body 字体栈** | `html uni-button, html uni-input { font-family: Arial }`（原生表单控件不继承页面字体，行盒高度不同会差 3px） |
  | ⑪ | `uni-label` 有子内容就挂 `.uni-label-pointer` | `html uni-label.uni-label-pointer { cursor: default }`（否则说明文字出现小手） |

### 2.2 ⚠️ uni 模板编译器会静默丢弃 pointer 事件

- **日期**：2026-10-07
- **背景 / 现象**：给进度条绑 `@pointerdown` / `@pointermove` / `@pointerup` 后处理器**一次都不触发**，
  而同一元素的 touch/mouse 绑定正常。
- **根因**：uni 的模板编译器**静默丢弃** pointer 事件（`uni.createSelectorQuery` 与原生 `PointerEvent`
  本身都没问题 —— 实测排除）。
- **结论**：需要鼠标支持就绑 `@mousedown`，并在拖动期间把 `mousemove/mouseup` 挂到 `document` 上
  （进度条就是这么做的，否则鼠标拖出轨道后松手会卡住）。阅读器根节点上原有的 pointer 滑动翻页
  在 H5 桌面端**其实是死的**（触摸端靠 `@touchstart/@touchend` 正常）。
- **位置**：`pages/reader/index.vue`。

### 2.3 ⚠️ `<image>` 的盒子模型

- **日期**：2026-09-22
- **背景 / 现象**：把 comic-web 写给原生 `<img>` 的 CSS 原样搬过来，阅读器整屏无图（或图很小）。
- **根因**：uni 的 `<image>` **不是 `<img>`**，而是包装元素 `<uni-image>`；真正画图的是它内部那个
  `<div>` 的 `background-image`。`uni-components/style/image.css` 给它**默认尺寸 `320px × 240px`**
  —— **`<uni-image>` 没有固有尺寸，宽高必须由 CSS 显式给**（原生 `<img>` 能靠图片自身撑开，它不能）。
- **结论**：两类错写法的表现与对策（清单）：

  | 写法 | 结果 |
  |---|---|
  | `width: auto; height: auto` | `<uni-image>` 是 inline-block、子节点全是绝对定位 / 百分比 → 收缩成 **0×0，整屏无图** |
  | 只写 `max-width` / `max-height` | `max-*` 只「限制」不「撑开」→ 回落到默认 **320×240，图很小** |

  `mode` 的语义（uni 源码 `IMAGE_MODES` / `FIX_MODES`）：

  | mode | 实现 | 适用 |
  |---|---|---|
  | `aspectFill` | `background-size: cover`（按框裁剪填满） | 封面 / 缩略图这类**有固定方框**的图 |
  | `aspectFit` | `background-size: contain`（等比不裁剪） | 单张居中阅读（等价原生 `img` + `max-width/max-height`） |
  | `widthFix` | 按 `offsetWidth ÷ 原图宽高比` 算高度 | 竖排连播（宽度定、高度自适应） |

- **补充**：`lazy-load` 在 uni-h5 基本不生效（Image 在 `onMounted` 就直接加载），别指望它省流量。

### 2.4 阅读器页面图尺寸（满幅，左右不留黑边）

- **日期**：2026-09-23
- **背景 / 现象**：`92vw` / `96vw` 时手机竖屏下左右各留 4vw / 2vw 的**黑边**（用户要求去掉）。
- **根因**：宽度没取到「视口里能放下的最大框」。
- **结论**：给 `<uni-image>` 的方框宽度取 `min(视口宽, 可用高度 × 0.705)`：

  | 模式 | 宽度 | 高度 |
  |---|---|---|
  | 横向（单张居中） | `min(100vw, calc((100vh - 40px) * 0.705))` | `calc(100vh - 40px)` |
  | 竖排（连播） | `min(100vw, 720px)` | `auto`（配 `widthFix`） |

  两项取 `min` 是为了**两种受限方向都覆盖**：手机竖屏走「宽度受限」（= `100vw`，图片铺满），
  桌面走「高度受限」（不会撑成一条巨大横幅）。
- **实测 / 补充**：⚠️ **竖排模式还额外中了一刀** —— uni 的 `<scroll-view>` 内层 `uni-scroll-view`
  在桌面 Chrome 下**实占 8px 滚动条宽**（实测 `offsetWidth - clientWidth = 8`），把 `100vw` 的图挤成
  382px、右侧露黑边。靠 `:deep(.uni-scroll-view)::-webkit-scrollbar { display:none }` +
  `scrollbar-width: none` 隐掉 —— 阅读区本来就是全幅暗色层，位置由底部进度条反映，不需要滚动条。
- **位置**：`pages/reader/index.vue`。

### 2.5 ⚠️ 弹层遮罩关闭（`@click.self` 的替代方案是坏的）

- **日期**：2026-09-22
- **背景 / 现象**：`@click.self` 在 uni 模板里不可靠，移植时改成「比较 `target` 与
  `currentTarget`」→ 遮罩点了**永远关不上**（阅读器目录 / 设置两个抽屉就中了）。
- **根因**：uni 会重写事件对象，`currentTarget` 不可靠地指向遮罩节点，判定恒真。
- **结论**：**正确写法**是遮罩上直接关，面板自己 `@click.stop` 拦住冒泡：

  ```vue
  <view v-if="showMenu" class="menu-mask" @click.stop="showMenu = false">
    <view class="chapter-menu" @click.stop> ... </view>
  </view>
  ```

  `.stop` 是 uni 支持的事件修饰符；遮罩上的 `.stop` 还顺带挡住点击冒泡到根节点（否则会触发根节点的翻页热区）。

### 2.6 ⚠️ 弹层的进场 / 退场动画

- **日期**：2026-09-22
- **背景 / 现象**：`v-if` 是「挂载即出现、卸载即消失」，只有进没有出 —— 观感就是**原地弹出 / 弹没**。
- **根因**：进出场统一走 CSS 动画 + 定时器（不用 `<transition>` 组件，离开时延迟卸载）。
- **结论**：统一用 **CSS 动画 + 定时器**：

  | 环节 | 做法 |
  |---|---|
  | 进场 | 元素自带 `animation: drawer-in 0.24s ...`（`translateX(100%) → 0`，抽屉贴右边缘），挂载即自动播放 |
  | 退场 | 关闭时**先挂 `.closing` 类**换成 `drawer-out`，等 `MENU_ANIM_MS` 到点再置 `v-if=false` 卸载；直接卸载会「秒没」 |
  | 幂等 | 关闭入口有多个（× 按钮 / 点遮罩 / 路由变化 / 菜单项），`closeMenu()` 用「已关闭或已在收起中则 return」保证不重复计时 |
  | 卸载前 | `onBeforeUnmount` 里 `clearTimeout`，别让定时器活过组件 |

- **实测 / 补充**：⚠️ **页间跳转必须等动画播完再 `router.push`** —— uni 的跳转是**页面级**的
  （每个页面各自持有自己的 `Layout`），push 的瞬间当前页连同 Layout 一起被卸载，抽屉会跟着秒消失、
  动画白做。`Layout.vue` 的 `goFromMenu()` 因此把 push 延后到动画结束。

### 2.7 ⚠️ 表格：`table` 换成 `view` 后必须用 flex 重新搭

- **日期**：2026-09-22
- **背景 / 现象**：把 `table/tr/th/td` 换成 `view` 后，每个单元格各占一行、整表塌成竖排
  （管理台日志页 / 授权页就中了）。
- **根因**：uni 没有 `<table>`；`view` 默认 `block`，而原版 CSS 靠 `border-collapse: collapse` +
  表格布局排版 —— **这套规则对块级 `view` 完全不生效**（只换标签"只做了一半"）。
- **结论**：`.u-tr { display: flex }` + 每列显式 `flex: 0 0 <宽度>`，最后一列 `flex: 1 1 0` 吃掉剩余宽度；
  原来写在 `td` 上的 `colspan="8"`（展开行 / 空态行）在 `view` 上无效，改成单格 `flex: 1`。
- **实测 / 补充**：**两个必踩的坑**（清单）：

  | 坑 | 现象 | 修法 |
  |---|---|---|
  | flex 项默认 `min-width: auto` | 列被「最窄内容」撑宽 —— 表头文字短、数据文字长（如级别列的 ERROR 徽标）→ **表头与数据行列宽对不上、整列错位** | 单元格一律加 `min-width: 0` |
  | 补完 `min-width: 0` 后，超长文本会溢出压到相邻列上 | 原版真表格列宽随内容自动变宽，`view` + flex 没有这个能力 | 可能超长的列自己截断：`overflow: hidden; text-overflow: ellipsis; white-space: nowrap`，完整值放 `title` |

### 2.8 ⚠️ 窄屏不许横向滚动条：表格一律降级成卡片

- **日期**：2026-09-23
- **背景 / 现象**：表格列一多（日志页 8 列固定宽合计 ≈ 944px），可视区只有 ~343px，
  横滚出来的是一条几乎没法用的细缝。用户明确「**不允许出现横向滑动条**」。
- **根因**：桌面表格是「固定列宽 + 外层容器横滚」的写法，窄屏下不可用。
- **结论**：`@media (max-width: 860px)` 里**整块换成纵向卡片**：

  | 页面 | 折叠态（默认） | 展开态（点行） |
  |---|---|---|
  | `admin/logs` | **时间 · 级别徽标 · 事件** 一行 + 消息（多行，不再截断） | 详情区补齐**源站 / 作品 / 章节 / 页数** + 记录器 / 任务 / 原因 / 接口 / 消息 / 异常堆栈 |
  | `admin/users` | 每段「标签 + 值」竖排（用户名 / 昵称 / 角色 / 注册时间 / 操作） | 无（行内已有操作按钮，没有隐藏字段） |

  四条通用做法（清单）：

  1. **根上消除横滚**：`.table-wrap { overflow: visible; max-height: none }`，
     `.user-table { overflow-x: visible }`。⚠️ 只改 `overflow-x: hidden` 是**掩耳盗铃** —— 内容仍超宽，
     会改成**页面级**横滚，一样是横向滑动条。
  2. **隐藏表头**（`.u-thead { display: none }`）：卡片每段自带语义，表头无意义。
  3. **必须重置列宽**：桌面的 `flex: 0 0 148px` 是**主轴**方向的基准。卡片改纵向后主轴变成**高度** ——
     不重置的话每段会被钉成 148px 高。（日志页卡片仍是横向主轴，但时间列钉死 148px 会把级别/事件挤出去，同样要重置。）
  4. **窄屏专用字段用 `.narrow-only` 二选一**，别用「按宽度分流」的脚本判断：
     日志页详情区里新增的 4 行（源站/作品/章节/页数）加 `.narrow-only`，宽屏 `display: none` ——
     桌面表格已有这几列，详情区再来一遍是重复。
     ⚠️ `display: none` 那条**必须写在 `@media` 之前**：两条选择器特异性相同，靠源码顺序决出胜负。

- **实测**：（2026-09-23，`docScrollWidth === docClientWidth` 为「无横滚」判据）

  | 页面 | 393×852 | 360×800 | 1280×900 |
  |---|---|---|---|
  | `admin/logs` | 无横滚；折叠 4 段；展开 9 项 kv + 堆栈 | 无横滚 | 8 列表格原样；`.narrow-only` 全 `display:none`；`::after` 为 `none` |
  | `admin/users` | 无横滚；表头隐藏；每格 flex + `.lbl` | — | 表头可见、行 `flex-direction: row`、`.lbl` `display:none`、`.c-user` basis 180px |
  | `admin/index` | 无横滚；单列 353px、边距 16/16 | 无横滚；卡片 320px、边距 16/16 | `.grid` 3 列 / `.maint-row` 2 列（与改动前一致） |

- **位置**：`pages/admin/{logs,users,index}.vue`。
- **后续**：⏳ **待办** —— 本端已改为「只保留移动形态」，但管理台三页的桌面表格与 860px 断点**尚未清理**
  （仍是「桌面表格 + 窄屏降级卡片」的响应式写法）。清理方式与其它页面一致（移动态提升为基础态、删断点），
  留待后续单独处理。在此之前，这套「窄屏降级」逻辑仍然有效、不要删。
- **补充**：**日志页的伸缩展开**复用原有的 `toggle()` / `.detail-row`（`v-if="expandedId === row.id"`），
  模板只加了 4 行 `.kv.narrow-only`，其余全靠一处媒体查询；窄屏展开箭头用 `.row::after` 绝对定位
  （`▾` / `.row.open` 时 `▴`），不参与 flex 布局、宽屏 `content` 为 `none`。
  **采集管理台（`admin/index`）** 是卡片不是表格，窄屏只要把 `.grid` / `.maint-row` 的
  `minmax(360px, 1fr)` 降成 `1fr`。⚠️ **360px 是硬下限**：窄屏内容区不足 360px 时列宽仍按 360px 撑开 ——
  实测 393 视口溢出 7px、**360 视口直接出整页横向滚动条**（`scrollWidth 376 > clientWidth 352`）。

## 三、布局与交互的坑

### 3.1 底栏导航与返回键

**形态**（2026-09-23 起为本端唯一形态，不再有宽窄屏之分；清单类，保留表格）：

| 区域 | 内容 |
|---|---|
| 顶栏左 | **返回上一层 `❮`**（`order: 0`，**仅二级页显示**，见下）—— 底栏三个 tab 是根页面，不显示 |
| 顶栏中 | 搜索框（吃掉剩余宽度） |
| 顶栏右 | 消息铃铛（**恒为跳独立消息页**）+ **☰ 菜单按钮**（`order: 5`，顶栏最右） |
| 底栏 | 首页 · 最近更新 · 分类（三等分，带图标，选中态变主题橙） |
| 菜单内 | **账号区**（未登录=整宽「登录」按钮 / 已登录=头像+昵称，**整行点击进「个人中心」**）+ **背景主题**（☀️ 明亮 / 🌙 夜间 分段控件）+ 全部导航（首页/分类/最近更新/排行/我的收藏与历史/**个人中心**/采集管理/授权管理） |

- 顶栏重排靠 **flex `order`**（返回 0 / 搜索 2 / 消息 3 / 菜单 5）、不改 DOM 顺序。
  ⚠️ 2026-10-07 起 **☰ 从最左移到最右、主题切换移进菜单**（原为「菜单 1 … 主题 4」）。
- 桌面专属元素（`.logo` / `.nav-links` / `.logout` / `.login-link` / `.user-chip`）**已从模板删除**，
  **账号入口只在菜单里**。

#### 顶栏返回键：层级返回，不依赖浏览历史（2026-10-09 重构）

- **背景 / 现象**：返回键原来走浏览历史 / 页面栈，用户报「一刷新页面返回的逻辑就失效了」——
  H5 一刷新这些就没了，彼时返回要么无效、要么落到意料之外的页面。
- **根因**：浏览器历史与 uni 页面栈都是易失状态，不可作为返回依据。
- **结论**：跳**固定上级**（`utils/router.ts` 的 `parentOf`）+ `redirectTo` **替换**当前页
  （不压栈、不依赖历史；来回多次页面栈不增长）。**新标签页里也成立**（详情页章节是 `openNewTab`
  开新标签进阅读器，那里必然无历史）。层级树：

  | 页面 | 上级 |
  |---|---|
  | `/reader/:comicId/:chapterId`（阅读器） | `/comic/:comicId`（它那一部的详情页） |
  | `/comic/:id`（详情） | `/latest`（最近更新页） |
  | `/admin/logs` · `/admin/users` · `/admin/schedule` · `/admin/comics` | `/admin`（采集管理） |
  | `/rank` · `/me` · `/messages` · `/login` · `/admin` | `/`（首页） |
  | `/` · `/latest` · `/search`（底栏 tab，根页面） | 无（不显示返回键） |

  阅读器的「←」与 `Esc` 走同一入口（`router.back()`）；**登录页的「← 返回」例外**：
  带了 `?redirect=` 就回它（**来处**，在 URL 上、刷新不失效），没带才按层级回首页。
- **位置**：`utils/router.ts`（`PARENTS` 表）、`components/Layout.vue`。
- **补充**：⚠️ **新增二级页要登记上级** —— 它与 `STATIC` 是两件事：`STATIC` 管「怎么去」（去程映射），
  `PARENTS` 管「怎么回」（回程层级）。漏登记会落到兜底 `/`（不报错，但返回目标不对）。

#### 断点只有 CSS 一处，脚本里没有宽度判断（2026-09-23）

- **背景 / 现象**：旧实现里有 `MOBILE_MAX` / `viewportWidth()`（用来判断点「用户头像」该展开菜单
  还是跳页）—— 已随「账号入口收进菜单」一并删除。
- **根因**：脚本判断宽度 + CSS 断点 = 两处阈值，容易「JS 改了、CSS 忘了改」的漂移。
- **结论**：**别再照抄回来**。菜单只由 ☰ 触发，不需要「按宽度分流」。若将来又要「按宽度分流」，
  用「两个元素 + CSS 二选一」（如原来的 `.msg-btn.wide-only` / `.narrow-only`），**不要回到脚本判断宽度**。

#### 消息铃铛只有一个（2026-09-23）

- **背景 / 现象**：原先「宽屏开浮层 / 窄屏跳页」靠两个同形铃铛 + CSS 二选一，已随桌面端删除。
- **结论**：现在**恒为跳独立消息页**。要恢复"按宽度分流"按上一条的「两个元素 + CSS 二选一」做。

#### 底栏 z-index 与底部安全区（2026-09-23）

- **背景 / 现象**：阅读器是 `position: fixed` + z-index 200 的全屏层，**会盖住底栏**。
- **结论**：底栏 z-index = **120**：高于内容、低于 toast（999）；与顶栏（z-index 100）同一处理方式，
  因此不需要额外排除逻辑。底栏带 `padding-bottom: env(safe-area-inset-bottom)`；
  `.page` 补了 `padding-bottom: 84px`（写成两条，`env()` 不被支持时回落第一条），否则最后一行会被底栏盖住。

**底栏图标（`src/utils/icons.ts`）**

- **背景 / 现象**：底栏三个图标是自绘 SVG，**运行时编码成 base64 data URI** 交给 uni 的 `<image>`。
- **根因 / 设计取舍**：
  - 不用裸 `<svg>` 标签 —— 项目约定「模板只用 uni 组件」，`<image>` 三端行为一致；
  - 不用 `.svg` 文件 —— `<image>` 对 svg **文件**的支持各端不一致；base64 data URI 最通用；
  - 不引图标库 —— 3 个图标不值得加依赖；
  - 不用 `btoa`（部分运行环境没有）→ 自带 ASCII 版 base64 编码器（SVG 内容全 ASCII），
    已与 `Buffer.toString('base64')` 逐字节比对通过。
- **结论**：**颜色写死在 SVG 里**（`<image>` 不认 `currentColor`）→ **主题 × 选中态 = 4 份**：
  `TAB_ICONS`（明亮）/ `TAB_ICONS_DARK`（夜间），各含 `off`/`on`；`Layout` 抽了个
  `tabIcon(path, on)` 按 `isDark` + `route.path === t.path` 选 `:src`。夜间那份不能省 —— 默认态
  用的是 `--text-2`，夜间该值变亮，用明亮那套在深底上基本看不见。
- **补充**：⚠️ `<image>` **必须显式给宽高**（uni 默认 320×240），这里 `.bn-icon { width: 22px; height: 22px }`。

### 3.2 封面网格与分页

#### 分页页面的每页条数要能被列数整除（2026-09-23）

- **背景 / 现象**：用户报「第一页最后一行最后一格空掉」。
- **根因**：`pageSize` 与列数不整除 → 末行留空格。
- **结论**：`search` 取 **`pageSize = 18`** = 3 列 × 6 行，正好填满。**别随手改回 20**：20 ÷ 3 = 6 行余 2，
  末行就空一格。（末页是余数页，留不齐属正常，例如分类页第 3 页 16 条 → 末行 1 个。）
  ⚠️ **`latest` 已不适用这条**（2026-10-09 改触底加载 + 日期分组）：它每组各是一个网格、
  末行本来就可能不满，18 只作为「一批拉多少」的批次大小，不承担「填满」职责。

#### 卡片字号由 ComicCard 的 ≤560 断点统一收紧（2026-09-23）

- **背景 / 现象**：手机列宽只有 **~110px**（390px 视口，含 16px 页面内边距 + 10px 间距）。
- **结论**：卡片的字号 / 内边距由 **`components/ComicCard.vue` 里的同名 ≤560 断点**统一收紧
  （标题 13px、作者/最新话 11px、角标 10px），作者名补了 `ellipsis`（原先没截断，窄卡片下会撑破行）。
  **改列数时记得一起看它。**

#### 行式列表不适用 3 列网格，别顺手改（2026-09-22）

- **背景 / 现象**：`我的 · 最近阅读`（`.row`，带「读到第 N 页」进度 + 续读/删除按钮）与
  `排行榜`（`.rank`，带排名序号 + 🔥热度）保持行式。
- **结论**：改成封面网格会丢掉这些信息 / 操作（已与用户确认）。

#### `.page` 的左右 16px 不能省（2026-09-23）

- **背景 / 现象**：`.page` 与 `.container` 同为单类选择器且 `.page` 在后面，简写 `padding`
  会把 `.container` 的 `0 16px` 整体覆盖成 0，窄屏下网格直接贴屏幕边缘。
- **根因**：原 comic-web 同此写法，属移植过来的既有问题。
- **结论**：`style.css` 里 `.page { padding: 20px 16px 48px }` 的左右 16px 保留，已修。

### 3.3 主题（明亮 / 夜间）的坑

#### `.theme-dark` 必须排在 `:root` 之后（2026-09-23）

- **背景 / 现象**：主题变量组（`.theme-dark`）与 `:root` 同为单类权重。
- **结论**：靠源码顺序取胜 —— `.theme-dark` 必须在后。**组件里不该再写死表面色**，配色全在变量组里。

#### 表面色选变量对照表（2026-09-23）

- **结论**：卡片/顶栏/面板/输入框 → `var(--card)`；占位底色、页面底 → `var(--bg)`；
  静默块（灰底小标签）→ `var(--mute)`；再淡一档的表面（表头/行 hover）→ `var(--surface-2)`；
  开关轨道 → `var(--track)`；滚动条 → `var(--scroll-thumb)`。
  **新增组件样式时按这套选变量，别写 `#fff`。**

#### 底栏图标要换第二套（2026-09-23）

- **背景 / 现象**：图标颜色是烘死在 SVG 里的（`<image>` 不认 `currentColor`），默认态用的是 `--text-2`，
  夜间该值变亮 → 不换图标在深底上基本看不见。
- **结论**：`utils/icons.ts` 导出 `TAB_ICONS` / `TAB_ICONS_DARK`，由 `Layout` 按 `isDark` 选用（见 §3.1）。

#### `.app-shell` 上不能写 `position` / `z-index` / `transform` / `filter`（2026-09-23）

- **背景 / 现象**：任一项都会形成层叠上下文或包含块，里面那两个 `position: fixed` 的抽屉/遮罩
  就压不过外面的底栏了（它们本就为此放在 `.nav` 之外）。
- **补充**：`min-height: 100vh` 让短内容页也铺满整屏（背景色由 `.app-shell` 承载）。

#### 个别带固定底色的徽标仍是浅底（2026-09-23，未做）

- **背景 / 现象**：管理台的 `.badge.warning`、`.src-tag.real`、`.msg-kind` 的来源色块，

### 3.4 首页的坑

## 四、排查规程：playwright MCP 实跑取证

> 规程类（步骤结构，不套字段块）。

**触发时机**：页面出现**请求报错 / 接口返回不对 / 样式错位 / 交互失效**时，**不必等用户要求**，
先在真浏览器里跑一遍再下结论。**禁止**只读源码就断言「应该是 XX 问题」—— 这类猜测在 uni 编译改写
（元素变 `uni-view`、样式运行时 `insertRule` 注入）后经常不成立。

**前提**：`npm run dev:h5` 已在 :5174 跑着；MCP 已在连接器管理页 Trust（改过 `mcp.json` 后需重新 Trust）。

**取证三件套**

| 目的 | 工具 | 关键参数 / 说明 |
|---|---|---|
| 看 JS 报错 / 警告 | `browser_console_messages` | 默认返回全部；先 `browser_navigate` 到目标页，再调它 |
| 看请求清单 | `browser_network_requests` | 列 URL / 方法 / 状态码 / 耗时，可过滤 |
| 看单条请求详情 | `browser_network_request` | 传 index，拿请求头、payload、响应体 |
| 看 DOM 结构 / 找元素 | `browser_snapshot` | 无障碍树，返回可点击的 `ref` |
| 直接算值 / 读全局 | `browser_evaluate` | 跑一段 JS，读 `localStorage`、算布局盒模型等 |

**典型流程**

1. `browser_navigate` 到 `http://localhost:5174/#/<目标路由>`（H5 是 hash 路由）。
2. 需要登录态时先走登录流程；token 落在 `localStorage.comic_web_token`，可 `browser_evaluate` 读出来核对。
3. 复现问题 → 读 `browser_console_messages` 拿报错 → 读 `browser_network_requests` 定位是哪条 `/api/*` 挂了 → `browser_network_request` 看响应体。
4. 样式问题：`browser_snapshot` 或 `browser_evaluate` 读 `getComputedStyle` / `getBoundingClientRect`，别靠肉眼读 CSS 文件推断。

### 4.1 URL 形态与登录态注入（2026-10-13 实测补充）

#### uni H5 的地址栏是 uni 自己的页面路径

- **背景 / 现象**：直接访问 `#/search` 这类 web 路径 → `Vue Router: No match found`，**页面空白无内容**
  （控制台无红色报错，极易误判成"数据没拉到"）。
- **结论**：地址必须用页面路径 —— `#/pages/search/index`、`#/pages/comic/index?id=43`。

#### 不知道密码时注入登录态做管理台验证

- **背景 / 现象**：验证管理台 UI 需要登录态，但账号密码不可知。
- **结论**：在 `browser_evaluate` 里用 **Web Crypto 生成 JWT**（HS256，密钥默认
  `comic-demo-secret-change-me`，payload 只要 `sub`/`username`/`iat`/`exp`），
  `localStorage.setItem('comic_web_token', tok)` 即可 —— uni 的 `setStorageSync` 对 **string 直接存原值**。
- **实测 / 补充**：
  - ⚠️ **工具输出里的 JWT 会被安全层改写**（变等长乱码，落文件也一样）—— 别在命令行里生成再粘贴，
    **要在浏览器内生成**；
  - ⚠️ `/api/auth/me` 的 `data` **直接是 user 对象**（不是 `{user}`）。

### 4.2 用桩拦截接口时的坑（2026-10-06）

#### 带查询串的接口，桩必须用 `*` 收尾

- **背景 / 现象**：`page.route('**/api/admin/tasks')` **匹配不到** `/api/admin/tasks?limit=20`，
  请求漏到真后端 → **401 → `request.ts` 清 token → 整页跳登录页**，症状是"页面空白 / 全部断言为假"，
  极容易误判成自己刚写的代码坏了。
- **根因**：glob 是按整串 URL 匹配的。
- **结论**：写成 `'**/api/admin/tasks*'`。

#### 拿不到内容时先看最终 URL 与控制台

- **结论**：跳登录页时 `page.url()` 会带 `#/pages/login/index?redirect=...`，控制台则有那条 401。
  先看这两个，比逐行读源码快得多。

#### 别用 `document.querySelectorAll('button')` 点界面

- **背景 / 现象**：表现为"点了但没反应"。
- **根因**：uni 把 `<button>` 渲染成 **`<uni-button>`**，按标签找会一个都找不到。
- **结论**：按类名找（`.msg-link` 等）或直接用快照的 `ref`。

### 4.3 MCP 不可用时：自动检测 + 补装（不等用户要求）

> 规程类（步骤结构）。

**第一步永远是「检测 playwright MCP 是否存在」—— 不要只看某个固定配置文件。**
同一个 MCP 可能由**用户级 / 项目级 / 其他 agent 的配置**提供，只翻 `~/.workbuddy/mcp.json` 会误判成
「不存在」而**重复写入**。按这个顺序检测：

1. `ToolSearch` 搜 `mcp__playwright__*`，看是否在工具索引里；
2. 查**连接器列表**里有没有 `playwright`。

**结果 A —— 确实不存在**（索引没有、连接器列表也没有）→ **写入标准配置并安装**

把下面这条**合并**进 `mcpServers`（**只加这一条，不要覆盖其他条目**）：

```json
"playwright": {
  "type": "stdio",
  "command": "npx",
  "args": [
    "-y",
    "@playwright/mcp@latest",
    "--browser=msedge",
    "--output-dir=C:/Users/caimf/.workbuddy/playwright-mcp-out"
  ],
  "disabled": false
}
```

写入位置：**用户级 `~/.workbuddy/mcp.json`**（默认落点；若本项目已有项目级配置且更合适，也可写那里，
但**先确认该位置确实没有 playwright 条目**）。

两个参数都是**必需**的：`--browser=msedge`（本机只有 Edge，不指定会去找 Chrome 而失败）；
`--output-dir`（不加会把自动命名快照落到工作区根的 `.playwright-mcp/`，污染仓库且不在 `.gitignore` 里）。

安装：**不需要单独 `npm i`** —— `npx -y` 首次运行会自动把 `@playwright/mcp` 拉到 npx 缓存；
已用过该 MCP 的机器上通常已缓存，写配置即可。

**结果 B —— 已存在，只是工具不在索引**（刚改过配置，主机把连接置回**待信任**）

→ **配置本身没坏，别重写、别重复添加**。这是正常现象，直接进下一步。

**两种结果的收尾都一样 —— 必须显式提示用户**

WorkBuddy **不会自动启用**新 MCP：需要用户到**连接器管理页右上角「自定义连接器」入口，
点 `playwright` 的 Trust**。**这条提示必须打出来，不能省略、不能只在心里想**；
Trust 完成后本会话的 `mcp__playwright__*` 才会回到索引。

**Trust 完成前**：不要静默退回「读代码猜」。可先用本机替代手段临时取证（直接 `curl` 打接口看响应、
无头浏览器 CDP 脚本、让用户贴控制台截图），并**说明这是临时手段**、已在等 Trust。

## 五、工程与协作的坑

### 5.1 ⚠️ AI 协作改 `src/` 会把 dev server 打挂

- **日期**：2026-10-06（已修）
- **背景 / 现象**：dev server 跑着的时候，用**原子写**的工具保存 `comic-front/src/**` 下任一文件，
  dev server **整个进程退出**，报错形如：
  `Error: EBUSY: resource busy or locked, watch '...\src\pages\admin\.schedule.vue.<pid>.<uuid>.tmpdir\schedule.vue.tmp'`
- **根因**：这类工具按「**同级** `.<文件名>.<pid>.<uuid>.tmpdir/` 里写 `.tmp`，写完再改名」落盘；
  chokidar（Vite 的 watcher）会去 watch **正被写者锁住**的那个临时文件 → 抛 `EBUSY`，
  而这是 watch 层的**未捕获错误** → node 直接退出。
- **结论**：已在 `vite.config.ts` 的 `server.watch.ignored` 里忽略 `**/*.tmpdir/**` 根治。
  改动 `vite.config.ts` 本身仍需重启 dev server 才生效。
- **补充**：若哪天又出现同类崩溃（别的工具换了个临时目录命名），照这个思路往 `ignored` 里加一条即可，
  而不是"改完代码记得手动重启" —— 那是治标。

### 5.2 ⚠️ `*/` 不能写进块注释（踩过两次）

- **日期**：2026-10-06
- **背景 / 现象**：定时任务那套文案里到处是 cron 例子，而 `*/15 * * * *` 这种步长写法
  **只要出现在 `/* */` 或 `/** */` 里，`*/` 就会提前闭合注释** —— 后面的文字变成非法代码，
  报错还指不到点上：

  | 位置 | 报错 | 症状 |
  |---|---|---|
  | CSS 注释（`schedule.vue` 的 `<style>`） | `[postcss] Unexpected '/'` | 样式块 500 → **整页白屏** |
  | TS 的 JSDoc（`types.ts`） | `Transform failed ... ERROR: Unexpected "*"` | 模块 500 → 页面加载失败 |

- **结论**：注释里用**文字描述**（"每隔 N 分钟用步长形式"），字面量留给模板 / 字符串 / HTML 文本 ——
  那些地方不受注释规则约束。
- **实测**：判断方法 —— 改完立刻按文件名向 Vite 取一次（`curl http://localhost:5174/src/xxx.ts`），
  非 200 就是编译失败了。

### 5.3 依赖版本锁（装任何前端工具前先看这条）

- **背景 / 现象**：2026-10-13 装 vitest / eslint 时连撞两次版本墙（ERESOLVE）。
- **根因**：本项目几个依赖是**精确锁版本**的，新工具的 peer 要求容易冲突。
- **结论**：

  | 依赖 | 锁定值 | 原因 |

### 5.4 后端契约变化后的类型同步（2026-10-13）

## 六、2026-10 前端基础设施重构（C / D 块）

### 6.1 `usePagedList`：分页状态机的抽取（2026-10-13）

- **背景 / 现象**：分页逻辑在 5 个页面**逐字重复**（`latest` 与 `rank` 的 `load`/`loadMore`/`reqId`
  一字不差；`search`/`admin-comics`/`admin-logs` 各抄了一遍带页码的变体）。
- **根因**：页面层没有共享模式，每个页面各自为政地写分页、竞态、失败处理。
- **结论**：抽到 `src/composables/usePagedList.ts`，封装三处**踩过坑的细节**：

  | 细节 | 不这么做的后果 |
  |---|---|
  | 竞态令牌 `reqId`（只认最后一次请求） | 切标签 / 切排序连发请求时，旧响应会盖掉新榜 |
  | **追加失败要页码回退** | 否则下次触底**跳过失败的那一页，永久少一页数据** |
  | **翻页（`goPage`）是替换、触底（`loadMore`）是追加** | 两种语义搞混会让列表显示错误内容（翻页写成追加：第 3 页显示 1~30 条） |
  | `ready` 只在「自己是最后一次请求」时置位 | 乱序返回时提前置位，首屏会先闪一下"暂无数据" |

  另有 `refresh()`（重拉当前页、页码不动，供"行内操作改数据后刷新"用，如补章后）。
- **位置**：`src/composables/usePagedList.ts`、`tests/usePagedList.test.ts`（6 例守卫）。
- **实测**：接入 4 页（latest / rank / search / admin-comics 用 `usePagedList`；**admin-logs 例外** ——
  它的「每页条数」可变，属特殊处理，只接 `Pager` 组件、保留自己的分页状态）。

### 6.2 `Pager` 组件：页码输入跳转的设计取舍（2026-10-13）

- **背景 / 现象**：4 处「上一页 + 页码文本 + 下一页」各写一遍；用户要求「**要有输入页码跳转到指定页面的功能**，
  现在只有上下一页不方便」。
- **根因**：分页条无组件化，且缺跳页能力。
- **结论**：抽 `components/Pager.vue`（只出 `@change` 事件、不碰状态），交互规则：
  - 输入页码**回车（`confirm` / 键盘「前往」）提交**；超界自动夹到 `[1, totalPages]`；与当前页相同则不触发；
  - **失焦恢复为当前页码**（防脏值残留）。
- **实测 / 补充**：⚠️ **刻意不做「跳转按钮」** —— 按钮点击会先让输入框失焦（值被恢复），
  跳转就读不到用户的输入了；只认 `confirm` 是跨端最可靠的提交方式。
- **位置**：`components/Pager.vue`、接入于 search / admin-comics / admin-logs / admin-users 四页。

### 6.3 修复的三个真 bug（2026-10-13）

- **背景 / 现象**：
  1. `admin/comics.vue` 的 `totalPages` 是 **NaN** —— `pageSize` 是普通数字却写了 `pageSize.value`
     （= `undefined`）→ 「下一页」按钮**永不禁用**、还能请求超页；
  2. `search` 页的 `load()` 是**裸 `await`**（无 try/catch）→ 接口挂掉 `loading` 永远为 true、
     页面卡在「搜索中…」；
  3. 首页 `onMounted` 同款裸 `await` → 任一步抛错则永久「加载中…」。
- **根因**：状态与请求处理手写、无统一兜底。
- **结论**：1 由接入 `usePagedList` 时顺带修复（`pageSize` 不再手工算 `totalPages`）；
  2 / 3 改为分路 `catch` + 错误态（首页另加「重试」入口；`search` 由 `usePagedList` 的 error 态接管）。

### 6.4 时间格式化收敛：8 处 → 1 处（2026-10-13）

- **背景 / 现象**：时间格式化在 7 个页面 + `stores/message.ts` 各写一份（共 8 处）。
- **根因**：无共享工具；且发现 **`fmtTime` 同名不同义** —— 在 `me` / `admin/*` 是 `YYYY-MM-DD HH:mm`，
  在 `comic` 却是 `M月D日`（光看调用点判断不出显示成什么）。
- **结论**：收进 `src/utils/format.ts`（`formatDateTime` / `formatRelative` / `formatMonthDay` /
  `formatCommentTime` / `formatInterval` / `formatHeat`）—— **函数名即口径**。
  `stores/message.ts` 的 `fmtMsgTime` 刻意未并（消息列表要更紧凑的 `MM-DD HH:mm`）。

### 6.5 ESLint + vitest 门禁（2026-10-13，D 块）

- **背景 / 现象**：三条写法约定（模板只用 uni 组件 / 自定义组件不用 `v-model` / CSS 只写类选择器）此前只在文档里，
  靠 review 自觉；6 处裸 `alert`（绕过统一弹窗出口）长期存在。
- **根因**："按规定调用"没有机器门禁。
- **结论**：ESLint 9 + vitest 3 接入（版本兼容坑见 §5.3），`package.json` 加 `lint` / `test` / `typecheck` / `check`；
  `check.sh` 同步（见根仓库 `scripts/check.sh`）。规则要点：
  - `no-alert` + `no-restricted-globals`（localStorage）+ `no-restricted-syntax`（`uni.request`）；
  - **例外放行** `src/api/request.ts` 与 `src/utils/**`（兼容层本身就是唯一允许碰平台 API 的地方）；
  - vue 规则用 `flat/essential` 而**不是** `recommended` —— 后者打开 1400+ 条排版 warning，把真问题淹没；
  - `no-undef` 关闭（TS 项目惯例；实测误报 `Event`/`PointerEvent` 等 13 处）；
  - `tests/conventions.test.ts` 用**源码扫描**守卫「自定义组件不用 v-model」（ESLint 查不了 vue 模板）。
- **实测**：首次跑扫出 30 个真问题，其中 6 处裸 `alert` 与 2 处死 import 已修。
